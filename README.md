# 本科毕业论文导师分配系统

面向 teaching operations office 的分配工具：导师池与学生提交两张表进去，一份可复现、
可解释、带 AI 复核意见的分配结果出来。ELM 只做信息抽取与事后复核，分配本身由确定性
的优化模型决定，因此同样的输入与参数重跑一定得到同样的结果，学生来质询时 office
拿得出依据。

## 安装与运行

```bash
pip install -r requirements.txt
streamlit run app.py
```

首次可以直接点「载入示例导师表 / 载入示例学生表」跑通全流程，再换成真实数据。

## 数据格式

导师表 `sample_supervisors.csv`

| 列 | 是否必填 | 说明 |
|---|---|---|
| supervisor_id | 必填 | 唯一标识 |
| name | 必填 | 姓名 |
| group | 必填 | 所属课题组 |
| research_areas | 必填 | 分号分隔的领域标签 |
| methods | 必填 | 分号分隔的方法标签 |
| keywords | 可选 | 自由文本，代表作、往年题目都可以放进来，进入文本相似度 |
| workload | 必填 | **本届**该导师的论文数上限，逐年重填 |
| min_load | 可选 | 下限，用于保证每位老师至少带几篇 |
| available | 可选 | 0 表示本届不带，休假或 sabbatical 填 0 |

学生表 `sample_students.csv`

| 列 | 是否必填 | 说明 |
|---|---|---|
| student_id | 必填 | target ID |
| project_title | 必填 | 题目 |
| abstract | 必填 | 摘要 |
| project_name | 可选 | 学生自己的项目名 |
| areas / methods | 可选 | 学生自填标签，也可由 ELM 抽取后回填 |
| references | 可选 | 参考文献，进入文本相似度 |
| preferred_supervisor_id | 可选 | 学生意向导师，作为加分项而非硬约束 |
| locked_supervisor_id | 可选 | office 人工锁定，强制保留该配对 |

## 优化模型

记 $s_{ij}$ 为学生 $i$ 与导师 $j$ 的匹配分，$x_{ij}\in\{0,1\}$ 为分配决策，
$u_i\in\{0,1\}$ 表示学生 $i$ 未被分配，$w_j$ 为导师 $j$ 的 workload，
$\underline{w}_j$ 为下限，$\theta$ 为 good match 门槛，$\tau$ 为 mismatch tolerance，
$\mathcal{A}$ 为通过 hard floor 与 top-k 筛选后的候选集合。

$$\max \sum_{(i,j)\in\mathcal{A}} s_{ij}x_{ij} - M_u\sum_i u_i - M_\ell \sum_j \sigma_j$$

$$\sum_{j:(i,j)\in\mathcal{A}} x_{ij} + u_i = 1 \quad \forall i$$
$$\sum_{i:(i,j)\in\mathcal{A}} x_{ij} \le w_j \quad \forall j$$
$$\sum_{i:(i,j)\in\mathcal{A}} x_{ij} + \sigma_j \ge \underline{w}_j \quad \forall j$$
$$\sum_{(i,j)\in\mathcal{A}:\, s_{ij}<\theta} x_{ij} \le \lfloor \tau n \rfloor$$

去掉最后一条容差约束之后，约束矩阵是运输问题的节点弧关联矩阵，全幺模，
LP 松弛的顶点解自然整数，不需要任何分支定界。容差约束是唯一破坏这一性质的地方，
因此提供两条求解路径：

- `lp`：把容差罚进目标函数，对乘子 $\lambda$ 做二分，全程只解运输 LP，快
- `milp`：容差写成真正的基数约束，交给 CBC / HiGHS / Gurobi，精确

实测两者在多组参数下目标值完全一致。规模参考（候选稀疏化 top-k = 25）：

| 规模 | 候选变量数 | LP + 二分 | CBC MILP |
|---|---|---|---|
| 300 生 / 90 师 | 7,395 | 0.6s | 1.3s |
| 900 生 / 150 师 | 22,500 | 0.2s | 5.7s |
| 2000 生 / 200 师 | 50,000 | 0.4s | 23.3s |

Gurobi 在这个规模上不必要，装了则 `auto` 会自动优先调用。

## 三个门槛参数的分工

- **hard floor**：低于此分的配对根本不进入模型。作用是兜底，宁可让学生进人工池，
  也不要把一个做定性组织行为的学生塞给只做随机优化的老师。
- **good threshold**：达到此分算合格匹配。
- **mismatch tolerance**：允许低于合格线的分配占比上限。调到 0 时模型宁可留下未分配
  学生也不做勉强配对，调松则未分配减少而平均质量下降，这条兑换关系由「容差前沿」
  一键扫出来，用于跟各组沟通。

## ELM 的三个用途

1. **抽取与标准化**：把学生自由文本的题目与摘要映射到受控词表。绝大部分 mismatch
   的根源是学生词汇混乱而不是算法不好，这一步的收益最大。同时给出选题清晰度评分，
   清晰度 1-2 的学生应当在分配之前退回补充材料。
2. **候选筛查**：对规则分排在前列的少数候选给出 0-100 的匹配判断，按较小权重
   混入总分，只做倾斜不做决定。
3. **事后复核**：读已经定稿的配对，逐条给出 ok / query / reject 与理由。模型的
   reject 是人工复查的排序依据，不是裁决。

## 数据保护

发往 ELM 的内容只包含匿名化 token、题目与摘要，姓名、学号、邮箱在 `strip_identifiers`
里被替换，token 与真实 ID 的映射只存在于本地进程内存。即便如此，正式使用前仍应走一次
学院的数据保护流程确认。

## 分批运行与轮次台账

`rounds.py` 维护一个 JSON 台账，记录每一轮已定的配对与各位导师的剩余 workload。
典型用法是先只跑 Business Management，提交入台账，导师剩余容量自动扣减，
两周后跑 Accounting & Finance 时面对的就是扣减后的池子。台账可复制、可归档、
可整轮回滚，每一轮都存下当时的参数，因此任何一轮都能原样重跑。

分批有代价，而且代价不小：先跑的 programme 把最合适的导师先挑走，最后一批吃亏。
界面里的「分批代价」把顺序分批的结果与一次性联合求解并排放，联合求解是所有
programme 同一天交材料时的上界，两者之差就是日程的价格。示例数据上不做预留时
最后一批只安置了 37 人中的 26 人、平均分低 0.027，按人数比例预留之后变成 29 人、
差距压到 0.0148，代价是第一批让出一点。这条数字拿给排在最后的项目主任看，
比任何口头保证都有说服力。

## 已经考虑进去的使用情况

| 情况 | 处理方式 |
|---|---|
| 只安排某一个或几个 programme | ③里勾选 programme，容量来源选「台账剩余」 |
| 后面还有批次没跑 | 预留策略选「按人数比例预留」，可再设每位导师保底名额 |
| 晚交、补交、重修的零散学生 | 直接再跑一轮，已定学生自动排除，只面对剩余容量 |
| 导师病假、离职、临时休假 | ⑤「导师退出」释放其名下学生，其余配对不动，回③只重跑这批人 |
| 导师整届不带 | 导师表 `available` 填 0 |
| 学生换题、休学、申请换导师 | ⑤「释放个别学生」，回到未分配池 |
| 亲属关系、申诉当事人、纪律委员会成员 | 禁配表硬性排除，不混进匹配分 |
| 某位导师只带特定 programme | 导师表 `programmes` 列，留空表示不限 |
| 某个组被热门选题淹没 | 组级上限，嵌套结构仍是网络流，不破坏整数性 |
| 要保证每位老师至少带几篇 | 导师表 `min_load` |
| 某几条必须按人工意见走 | 学生表 `locked_supervisor_id` 强制保留 |
| 某一轮参数跑错了 | ⑤整轮撤销，容量释放回池子 |
| 学生质询为什么不是别的导师 | 「申诉预案」列出 wasteful 与 blocking 两类配对及原因 |
| 需要向下一年度交接 | 导出「更新 workload 后的导师表」直接作为下一轮输入 |
| 需要复现某次结果 | ⑥参数存档 JSON，同参数重跑结果一致 |

## 文件

- `app.py` — Streamlit 界面
- `matching_core.py` — 打分与优化核心，不依赖 Streamlit 与 ELM，可单独调用或写脚本批量试算
- `elm_client.py` — ELM 客户端，OpenAI 兼容，换平台只需改 base URL
- `rounds.py` — 轮次台账、容量预留、分批代价测算
- `sample_supervisors.csv` / `sample_students.csv` / `sample_blocked_pairs.csv` — 六个组、108 位导师、455 名学生、四个 programme 的示例数据
